# Фокус — карта продукта v2

> Обновлённая концепция по итогам сессии 04.07.2026. Заменяет раздел «Структура продукта» в конституции. Документ — источник правды для ТЗ по модулям.

---

## 1. Концепция

**Фокус — AI-first таск-трекер.** Понятная категория, одно ключевое отличие: AI. Внутри — всё, что нужно человеку, который ведёт своё дело: клиенты → проекты → задачи → время → деньги → аналитика. Person-first: ядро строится вокруг одного человека, команда подключается как расширение (shared workspace, видимость).

Философия неизменна: снижать когнитивную нагрузку. Пользователь всегда понимает, что важно прямо сейчас, и не думает, куда идти и что делать.

**Целевой пользователь:** фрилансер, самозанятый, предприниматель с небольшой командой. Русский рынок.

**Отстройка от конкурентов:** Яндекс.Трекер и корпоративные ТМС — про процессы и менеджерский контроль. Мы — про человека и его дело целиком, включая деньги и реальную занятость; команда — это расширение личного пространства, а не наоборот.

**AI-принципы (без изменений):**
- Decision Engine — детерминированный код; LLM — только объяснения и NL-парсинг
- Доверие зарабатывается постепенно: наблюдение → подсказки → действия
- Чат — глобальная строка внизу всех экранов, а не раздел: интеллект размазан по продукту

## 2. Разделы продукта

### 2.1 Деск
Рабочий стол. Первый экран дня.
- Центр: текстовое саммари — «Привет, {имя}, сегодня 3 задачи, 1 встреча...»
- Виджеты: создаются/удаляются пользователем (набор продумаем отдельно)
- Фоновая картинка. При переходе на Фокус фон блюрится и уходит в низкую opacity — единое визуальное пространство
- **Архитектура:** фон живёт в общем layout-слое, экраны рендерятся поверх

### 2.2 Фокус
План на день. Ключевой раздел — режим «работаю».
- Вертикальный список карточек: сегодня сверху, дальше по дням
- Дни сворачиваются/разворачиваются
- Выполненные помечаются, на следующий день скрываются в Журнал
- Многодневная задача (начало–конец) показывается в каждом дне своего диапазона с пометкой дедлайна
- Порядок внутри дня — по системе выдачи (см. §4)

### 2.3 План
Недельный календарь. Режим «планирую».
- Слайдер по неделям
- Задачи — сокращённые карточки; перетаскивание и растягивание
- Задачи без времени — отдельной полосой «без времени» в дне
- Основной сценарий: открыл бэклог-панель → растащил задачи по неделе

### 2.4 Задачи
Полная база задач.
- Виды: список и канбан
- Группировки: по сроку, по проекту
- Фильтр «Бэклог» (задачи без дат)

### 2.5 Проекты
Отдельный раздел со своими карточками.
- Карточка: название, описание, сроки, статус, сумма, клиент (опционально), этапы
- **Этапы (stages):** название, дедлайн, статус — новая сущность
- Виды: список/таблица + таймлайн (полоски проектов с насечками этапов). Роадмап, НЕ Гант
- Своя группировка

### 2.6 Клиенты
Лёгкая CRM.
- Вкладка «Клиенты»: карточки клиентов, привязка к проектам, суммы
- Вкладка «Финансы»: платежи колонками — план / ждём / оплачен. Платёж: сумма, проект/клиент, статус, дата
- В v1 — только трекинг. Счета, акты, банк-интеграция — дальний бэклог

### 2.7 Аналитика
- Ключевые графики из коробки + конструктор дополнительных
- Источники: время (единая модель), задачи, деньги, дневник занятости
- Детали — в отдельном обсуждении модуля

### 2.8 Заметки
Стикеры: текст + форматирование.
- Ключевая механика: выделить строки → «Создать задачи» (ПКМ на десктопе, всплывающая кнопка на таче)
- Точка входа NL-парсинга: выделенный текст разбирается в задачи с датами и полями

### 2.9 Дневник занятости
Сведение реальности с планом. Заполняется по желанию в конце дня.
- Дневные слоты по часам: что реально делал, тип задачи (пресеты + кастомные)
- **Единая модель времени с таймером:** таймер пишет слоты автоматически, дневник закрывает дырки руками. Предзаполненные слоты не трогаем — юзер досыпает только пустое
- Данные ложатся в основу обучения модели: план vs реальность
- Выход в аналитику: «чем реально занимаешься, где проблема»

### 2.10 Служебные
- **Журнал** — лог завершённых задач
- **Корзина** — восстановление, автоочистка через N дней
- **Настройки** — профиль, кастомные статусы, стартовый экран, уровень доверия AI, позже биллинг и команда

## 3. Сквозные механики

- **Чат с AI:** постоянная строка внизу на всех экранах. При наборе разворачивается, после отправки интерфейс блюрится и происходит переход в чат-вид. Чат видит контекст текущего экрана. Потенциально — единая точка ввода (вопросы + создание задач через NL-парсинг)
- **Бэклог-панель:** глобальный виджет, открывается на любой странице. Все задачи без дат, быстрое редактирование прямо в панели, drag в План
- **Канбаны:** везде, где есть — колонки редактируемые. Реализация через кастомные статусы, пер-контекстные наборы (задачи / финансы)
- **Фон + блюр:** общий layout-слой на все экраны
- **Повторяющиеся задачи:** правило повторения у задачи («каждый месяц 1-го», «каждый пн»). База для юзера: счета, отчёты, регулярные созвоны
- **Telegram-бот:** двусторонний. Туда — уведомления и пропуш («Ждём ОС висит 3 дня»), оттуда — быстрый ввод текстом/голосом → NL-парсинг → задача в инбоксе. Потенциально главный канал привлечения
- **Глобальный поиск:** Cmd+K по задачам, проектам, клиентам, заметкам (cmdk уже в стеке)
- **NL-парсинг:** быстрый ввод и заметки → структурированные задачи

## 4. Система выдачи (Decision Engine v0)

Порядок задач внутри дня в Фокусе. Детерминированный, каждое правило объяснимо одной фразой.

**Группа A — задачи со временем:** по времени начала.
**Группа B — без времени:**
1. Просроченные — наверх
2. По приоритету (высокий → низкий)
3. При равном приоритете — ближе дедлайн (задачи / этапа / проекта)
4. При полном равенстве — старее созданная выше

**Открытый вопрос:** группа B над группой A или под? (Аргумент за «над»: слотовые напомнят о себе временем, бесслотовые должны мозолить глаза.)

LLM-слой позже проговаривает правила юзеру: «эта выше, потому что дедлайн этапа в четверг».

| statuses | Пер-контекстные наборы (задачи, финансы) |
| projects | + сумма, client_id (опционально), связь с этапами |

## 6. Зафиксированные решения

1. Позиционирование: AI-first таск-трекер, person-first; команда — расширение, не отдельный режим
2. Стартовый экран: Деск при первом заходе дня → дальше Фокус; настройка в профиле
3. Порядок в Фокусе: слоты → детерминированный скоринг (§4)
4. У задачи начало и конец с датой и временем, оба опциональны
5. Многодневная задача видна в Фокусе каждый день диапазона
6. Фокус = исполнение дня, План = раскладка недели
7. Бэклог = глобальная панель, не раздел
8. Канбан-колонки редактируемые везде
9. Дневник и таймер — одна модель времени, дневник только досыпает дырки
10. Банк-интеграция — дальний бэклог
11. Порядок в v1 задач: список + канбан, без других видов
12. Повторяющиеся задачи и Telegram-бот — обязательные части продукта
13. Онбординг — в формате чата: первый диалог = обучение главному жесту продукта
14. Экспорт данных в CSV (минимум — аналитика и финансы): дверь наружу как часть доверия

## 8. Открытые вопросы

1. Группа B над или под группой A в выдаче дня (§4)
2. Набор виджетов Деска
3. Состав ключевых графиков Аналитики
4. LLM-провайдер (GigaChat Lite / YandexGPT Lite / Sonnet-класс) — с учётом приватности: данные клиентов и финансы юзера в западную модель = риск 152-ФЗ. Вариант: российская модель для чувствительного, + настройка «что AI видит»
5. Таймзоны: задачи со временем при смене пояса юзером — правило хранения (UTC + tz юзера) заложить при реализации слотов
6. Детали командного режима (дальняя фаза), включая видимость финансов в общем воркспейсе

## 9. Порядок разработки (черновик)

- **Фаза 0 — стабилизация:** версии в package.json, enum activity_log
- **Фаза 1 — ядро:** схема §5, Задачи (список+канбан), Проекты+этапы, Фокус, План, бэклог-панель, повторяющиеся задачи, поиск Cmd+K
- **Фаза 2 — обвязка бизнеса:** Клиенты, Финансы, Заметки, Дневник, Журнал, Корзина
- **Фаза 3 — Деск и Аналитика:** виджеты, саммари, графики, экспорт CSV
- **Фаза 4 — AI-слой:** NL-парсинг, объяснения выдачи, подсказки, Telegram-бот
- **Фаза 5 — продукт:** онбординг-чат, биллинг, лендинг, команда

Порядок фаз обсуждаемый — финализируем перед стартом ТЗ.
