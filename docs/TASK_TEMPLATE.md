## 8. Технические ограничения проекта ⚠️

| Тема | Правило |
|---|---|
| **React 18.2** | Нет `useActionState`/`useOptimistic`. Серверные экшены вызывать напрямую + `useTransition`/`useState` |
| **Supabase RLS** | Только `authenticated`; при insert обязательно проставлять `owner_id`; фильтр по владельцу делает RLS |
| **Типы** | После любой миграции — перегенерить `database.types.ts` (форма с `Relationships`), иначе insert/update схлопнется в `never` |
| **env / mock** | `hasSupabasePublicEnv()`: без переменных — mock и без гейта. Новые `NEXT_PUBLIC_*` **вручную добавить в Vercel** (Production + Preview) |
| **Серверные экшены** | В начале guard на отсутствие env → понятная ошибка, не 500 |
| **middleware** | Новые публичные роуты добавить в `PUBLIC_PREFIXES` (`lib/supabase/middleware.ts`) |
| **Почта** | Подтверждение email ВКЛ; Supabase **Site URL** = прод-домен, иначе письма ведут на localhost |
| **Деплой-защита** | Preview и прод за Vercel SSO; проверять через сервисный обход (`get_access_to_vercel_url`) |
| **ESLint в worktree** | В `.eslintrc.json` стоит `"root": true` (иначе конфликт с родительским конфигом при вложенном worktree) |

## Мини-пример

> **1. Цель:** группировать задачи по проектам.
> **2. Контекст:** таблица `projects` уже есть; `tasks.project_id` (FK) есть; UI/экшенов нет.
> **3. Критерии:** список проектов на `/projects` (пусто → плейсхолдер); создание/переименование/удаление; задача может иметь `project_id`; чужое не видно (RLS).
> **4. Область:** входит CRUD проектов; не входит шаринг, цвета, drag-and-drop.
> **5. БД:** миграции не нужны → типы не трогаем.
> **6. Auth:** только свои (`requireUser`).
> **7. UI:** `/projects` — список + пустое состояние; форма создания; dropdown «⋯» удалить.
> **9. Проверка:** typecheck/lint/build + создать проект в проде.
